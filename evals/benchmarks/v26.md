## Baseline and confounds (named, per POLICY §9)

**The comparison is against v24, not v25.** v25 was a partial run by the owner's
decision — two scenarios of eight, no idempotency and no mutation pass — so the
last full measurement is `benchmarks/v24.md` (214/214, mutations 214/214,
idempotency zero ×3).

Confounds a reader must hold when comparing v26 to v24:

1. **The corpus itself changed.** `audit-engine-absent` is retired (T-13.10,
   the owner's ruling): it falsified check 15's engine-absent branch, which this
   edition deletes. `evals.json` carries 9 entries where v24 had 10, and the
   graded scenario set is 8 directories where v24 had 9. A total that is smaller
   than v24's is expected arithmetic, not a regression — the per-scenario rows
   are where a regression would show.
2. **The law renamed the instrument.** Every scenario whose agent used to run
   `python3 docs/ai/engine.py <job>` now runs `legislator <job>`. A failure of
   the shape "the agent called a command that no longer exists" is a **law**
   class finding against the delivered text, not a model failure — classify
   before fixing (POLICY §4).
3. **The audit's exit contract moved.** Info no longer raises the exit code
   (T-13.2), and a clean repository on an untagged edition prints an
   `arm-integrity` Info line rather than `No findings.`. Assertions reading the
   clean shape were re-cut in the same pass; a scenario disagreeing here is
   measuring the old contract.
4. **The .NET suite is run by `check_dotnet.sh`, not `dotnet test`** (T-13.9) —
   the latter discovers zero tests on this SDK. The 656 above came from the
   module binaries directly.
