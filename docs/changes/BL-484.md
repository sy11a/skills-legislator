## changelog

- **Edition 28: core rules are delivered on demand.** The entry document imports only the always-tier law (`pair-development.md`, `decision-gate.md`); the other nine core rules and `docs/okf/codebase-map.md` are still delivered byte-for-byte but reached by a `### Read on demand` pointer block, one line each, `- Before <trigger>, read <path> — it is law, not a reference.` `opencode.json`'s `instructions` lists the always tier only. The template `AGENTS.md.tpl` is the single source of each rule's tier: the upgrade report reads it and, for a rule the entry document still `@`-imports, proposes removing the import and adding the template's own pointer line together. A pointer the owner reworded is left alone. The manifest-less legislation marker moves to `core/pair-development.md`. A project rule may also be on demand (`core/project-rules.md`) ([BL-484](docs/cases/BL-484-core-rules-on-demand/spec.md)).

## journal

- Why: every session and every subagent of a legislated repository loaded all eleven core rules on its first call. Measured in Architector on 2026-10-02 (`sy11a/sy11a_ctxops` plan 0010): the core files were 30,747 chars of the 95,940-char `instructions` attachment; a subagent with a new brief writes all of it to cache again.
- Tier source: a first draft kept the split as a closed C# set mirrored in Python; the refutation round replaced it with the template itself (an `@` line is always tier, a path named on any other line is on demand), so the tier lives in one place and the proposed pointer text is the template's own line. The map's tier comes from the template too: no C# special case.
- The template path values (`template_core_prefix`, `template_codebase_map_path`) stay in the options model (C-03); a value the parser cannot use fails the report with a named error rather than silently falling back to the always tier.
- Risk carried: on-demand law works only if the session reads it at the trigger. Each pointer names the moment the rule starts governing, never after it; stage skills that run a trigger should name the file (follow-up outside this repository).
- Benchmark run, 2026-10-02: the grader's own `agents_md_imports_all_core` still asserted the eleven-`@import` shape edition 28 retires, going red in three scenarios the moment the entry document stopped importing the on-demand rules. Replaced with `agents_md_core_tiers_wired_correctly`, derived from `AGENTS.md.tpl` rather than a second, driftable copy of the tier list.
- A worker first classified `harvest_lists_decimal_money_rule`'s red in `legacy-migration` as model-class; refuted by a re-run (red again) and by a control run of the same scenario on `master` (edition 27, release digests blanked in a scratch worktree), which passed 28/28 with the same money candidate present — same-tree, branch-only, not the model. Diagnosis: Step 7 test (2)'s "not already covered" never said how coverage is established, so the agent took a visible stack `@import` line as coverage, a signal edition 28 makes unreliable. Fixed in `skill/SKILL.md` Step 7 test (2) and named directly in `skill/references/migration.md:20` — carving a line out of the entry document is not the same act as reading the rule it carves and checking the candidate against it.
