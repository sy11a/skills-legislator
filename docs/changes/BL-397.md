## changelog

- **Edition v27: the retirement and the declaration move in one act.** Edition 26 retires `docs/ai/engine.py`, and four governed repositories declare that file as their own gate — in hand-authored instance data the legislator owns nothing of, foundry's in `tools/gate.sh` rather than prose. The day any of them upgraded was the day its declared gate named a file that is gone. `apply` now sweeps, before its first write, for commands naming a path **this run is about to retire**: it rewrites the declaration homes — the entry document, `.claude/rules/**`, the scripts under `tools/` the repository owns — from `python3 <retired> <job>` to `legislator <job>`, in place; it **stops the run at exit 4** where a line *runs* a retired path in a shape it cannot rewrite whole, naming the file and the line, with the retirement not performed either; and it counts rather than rewrites a record — a case, a journal day, an ADR, a change fragment, the changelog, a generated mirror, the OKF bundle's human class and anything under a `tests/` or `fixtures/` path — because those state what was true when they were written. **A line that merely names a retired path is a mention, never a refusal**: every entry document imports its rule files by path, so refusing on a mention refused every upgrade that retires a rule or drops a stack. The rule keys on what the run retires, not on `engine.py`, so a later edition retiring something else is covered by the same act ([BL-397](docs/cases/BL-397-the-upgrade-moves-the-declaration/spec.md), `#60`, `sy11a/Architector#448`).

## journal

- The decision was the whole case: `sy11a/Architector#448` left open *"whether legislator's own migration should perform that rewrite"*, and the alternative it was weighed against is a standing order that a human performs both acts together — which is the class of unenforced law this fleet has spent the week repairing. Ruled: the migration does it, because the edition knows what it stopped delivering and the repository does not. Dead end worth recording, from before this case: moving clerk's declaration **ahead** of its upgrade was tried and refused by its own refutation round — it adds a binary the repository tells no contributor to install, and it makes the entry document contradict the edition-25 law it imports. Both orderings are traps; that is why the two acts had to become one. The measurement that matters: over scratch copies of all four repositories the migration moves eleven declarations in seven files — foundry's `tools/gate.sh` and the `.claude/rules/verification.md` rows it is reconciled against, in one run — and over all eight scenarios of this repository's own e2e corpus, `upgrade` and `upgrade-drop-stack` included. Open, and deliberately not taken here: the four repositories take edition 27 on the operator's ordering, and the standing order in `#448` lifts as each does; a published `27.0.0` binary and the e2e benchmark re-run against it are owed first, and `evals/benchmarks/v27.md` says so.
