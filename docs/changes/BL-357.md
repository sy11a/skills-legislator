## changelog

- The verification-bindings file gains a declared form, a template and an enforcing check: `core/verification.md` states that a gate is one row of a three-column table read by a machine, the skill ships the `.claude/rules/verification.md` it had always told repositories to create, and audit check 22 reports a file that declares no readable row — which is the state two products shipped a whole release in ([BL-357](docs/cases/BL-357-bindings-form/summary.md), `sy11a/Architector#398`).

## journal

- Decided with its reasoning: the check **mirrors the kernel's parse exactly** — three cells between four pipes, `Gate` header and separator skipped — rather than being more generous. A check kinder than the reader it stands in for reports a green that reader will not honour, which is the defect one level up. Decided the other way on absence: a file that is *absent* is silent here, because `core/verification.md` declares absence a lawful fallback; that the merge queue handles absence *worse* than zero rows (it throws rather than parking) is a kernel defect and not this check's to report. Verified rather than assumed: run against `aidispatcher` and `runpool` as they stand, the check fires on both — the two products that shipped Release 2 with gates the kernel reads as none. Open: the law half and the check are here, and **the kernel half is not** — the merge queue still reports green over zero rows where the release end refuses, and that is `sy11a/Architector#398`'s remaining part in foundry.
