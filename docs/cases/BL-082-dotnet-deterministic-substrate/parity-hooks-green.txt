BL-082 T-11 — the hooks ruler on the published binary, and what the number is worth.

MEASURED ARM. `PARITY_HOOK_CMD=artifacts/linux-x64/legislator python3
evals/check_hooks.py` — 65 ok / 0 FAIL, exit 0. This is the first time the hooks
ruler has been driven against the binary at all: it was last measured in T-06 at
32 ok / 33 FAIL, under the `LEGISLATOR_*` name collision that made that number
untrustworthy, and the rename to PARITY_HOOK_CMD in T-07 left it unmeasured for
four tasks. 65 call sites over 59 unique labels.

WHAT THE NUMBER IS NOT. Re-run with a PERMISSIVE arm — `PARITY_HOOK_CMD=/bin/true`,
a hook that only ever allows — and the ruler reports 44 ok / 21 FAIL. So of the 65
call sites only 21 assert a refusal and die when the arm stops refusing; the other
44 are satisfied by a hook that does nothing. Twelve of those 44 never drive the arm
at all (the hooks.json shape checks, the two R-702 launcher checks which run the
Python command line through a PATH shim whatever the arm is, and the Bash-entry
check); the remaining thirty-odd are assertions of ALLOW, and a permissive hook is
the one thing that satisfies every one of them.

That is not a defect of these twins but the shape of this ruler: a guard is mostly
silence, and silence is cheap to imitate. What makes the allow-labels non-vacuous is
the block-label beside them in the same hook — except for format_on_edit, which has
no block at all: its four labels assert exit 0 and no output, and a hook that runs no
formatter passes them. That hook's real coverage is its twelve unit tests, which
assert on FakeProcessRunner.Calls. Named at the red review, measured here.

The dead-arm probe the engine side uses (/bin/false) says nothing here: exit 1 is
neither allow nor block, so every label fails and the run proves only that the arm
was reached. /bin/true is this ruler's equivalent question.

TWO LABELS NEVER RUN ON A HEALTHY MACHINE. `git available for guard_git_conduct.py
tests` and `git available for okf_sync_check.py tests` are asserted only inside the
`if not have_git` branch, as failures. With git present they print nothing at all,
which is why their twin asserts the same condition rather than a behaviour.

LEDGER. 8 — three engine labels (T-12) and the five whose subject T-13 removes.

The engine ruler was re-measured on the same binary and is unmoved: 142 ok / 0 FAIL.
