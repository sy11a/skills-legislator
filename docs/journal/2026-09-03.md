## BL-082 — stage 6, build: T-10, the write path (`apply`, `verify`, `report`)

The last engine task before the hooks. `apply`, `verify` and `report` are
ported, and with them the run record, the keep rules, the owned set and the v14
file model. The engine ruler reads 142 ok / 0 FAIL on the published binary, the
suite is 458/458, the artifact is 5 075 544 bytes, and the label ledger fell
from 96 to 60 in the same commit as the thirty-six twins that lowered it.

The task opened with a decision gate, not with code. The plan's Task 10 carried
the case-sensitivity item as "an audit check added beside `apply`", and that is
where it collided with the port's own contract: the audit's check set is law —
`SKILL.md` § Audit numbers exactly seventeen and `AuditChecks.Order` calls the
list law content — and the two arms are compared byte for byte. An eighteenth
check only the .NET arm knows makes the arms unequal by construction, in the
audit and in `report`'s `## Health`. Adding it honestly to both means editing
`skill/SKILL.md` and the Python engine mid-port, which drags a VERSION bump and
the full e2e benchmark out of order. The operator ruled option (a): the
mechanism lands here as `OwnedSet.CaseCollisions` with its own unit tests, no
audit slug and no twin, and its wiring into the pinned order and into the law
text moves to T-13, the task that already rewrites both. The promise is kept
where it was made — beside `apply`, where the owned set is written and a
collision becomes observable — without the port telling two stories.

Red first, and the prediction held on all four counts: `Legislator.Engine.Tests`
did not compile, six errors naming the types this task creates; the thirty-six
twins of the ruler's v24 section failed on `unknown job`; the ledger said "fell
to 60", which is the independent confirmation that ownership is thirty-six and
not the thirty-one the FAIL count alone would suggest; and the orphan direction
stayed green, so no label was invented. Five of the thirty-six were **vacuously
green** before the task — the exit-2 collision again, where an unknown job also
exits 2 and an assertion of absence holds over an engine that did nothing. They

run to have exited 0 and printed something beside the absence it asserts.

The red review accepted twelve departures from the plan's letter. The two that
change shapes other tasks own: `SkillArguments` keeps its flags as an ordered
list rather than a map, because `--keep-add` and `--keep-remove` repeat and a
map silently keeps the last; and `OwnedSet` owns the delivery map in both

consumer and its private `SkillSourceOf` deleted — two mappings could disagree
about which files the package authors, and the disagreement would read as a
clean audit over a file `apply` never delivered. A thirteenth surfaced in green
by the same rule: `Detection` was extracted out of `DetectJob` because `apply`
must read the mode exactly as `detect` reads it, or an apply could decide one
thing while the detect the owner ran a minute earlier showed another. That is
the fifth time this case has extracted at the moment a second consumer appeared,
and it has never once been tidiness.

`ApplyStop` is not an exception. The Python raises and the CLI catches; here the

**A fake that lied, for the second time in this case.**
`MockFileSystem.CreateSymbolicLink` resolves a relative target against the
process's current directory and requires it to exist; the real `System.IO` does
not resolve the target at creation at all. The product's link is relative on
purpose — an absolute one breaks when the repository moves, and both the Python
and the ruler read it back as `AGENTS.md` — so the fixture was pointed at the
repository root rather than the product bent to the fake, with the divergence
written down where it bites. At the red review I had told the operator that
`TempDirectory` would not be needed and everything was expressible in the fake;
that was wrong, and the correction was named at the ownership window rather than
buried in a commit. The first such divergence was reading a directory (T-08).

## BL-082 — stage 6, build: T-11, the four Claude Code hooks

The last porting task. `guard_owned_files`, `guard_git_conduct`,
`format_on_edit` and `okf_sync_check` are .NET, behind an `IHook` the CLI
dispatches to as `legislator hook <name>`. The host reads stdin and renders the
answer; the hooks touch neither. The catch-all lives in `HookCommand` rather
than in each hook, because what must hold is the CONTRACT — exit 0 or exit 2,
never a third code and never an exception escaping — including for a bug no
hook's own code foresaw. Composition sits inside that guard on purpose: a
malformed `legislator.yaml` is a loud exit 2 for a job, and exit 2 from a hook
blocks the edit that triggered it. The suite is 629/629, the artifact
5 141 688 bytes, and the label ledger fell 62 → 8.

The task opened on a decision gate. The plan's Step 7 rewrites
`plugin/hooks/hooks.json` to name the binary, and five `check_hooks.py`
assertions are bound to the Python form it removes — the `.py` command shape,
the script-exists check, the Bash-entry check and the two R-702 launcher checks
— one of which does not merely fail but CRASHES the ruler, `guard_entry =
next(...)` raising an uncaught `StopIteration` the moment no command names
`guard_owned_files.py`. T-13 already owns `check_hooks.py` and the deletion of
the scripts, and the T-06 journal had already placed the launcher tests there;
the plan simply put the rewrite two tasks early. The operator moved Step 7 to
T-13 and ruled that the five labels are not twinned here either — so the ledger
stops at 8 rather than 3, with the remainder addressed rather than hoped away,
and no twin is written to be deleted.

Three findings worth keeping. **`GitLog.Ask` trims**, and porcelain's first two
columns are the status: read through `Ask`, every path came back shifted by one
character and no directory ever matched, which turned `dirty src/ only: exit 2`
into a silent allow — and, worse, made `dirty src/ + docs/okf/: exit 0` pass
for the wrong reason. `GitLog.Read` now sits beside `Ask` for formats whose
leading whitespace is data. **The Python parses before it decides**: a
malformed payload never reaches the logic, where a `HookPayload` that merely
answers null lets a hook needing no field — `okf_sync_check` — walk on and
block. Every hook now returns allow on an unusable payload explicitly, rather
than by the accident of a missing lookup. **The second-consumer rule fired for
the sixth time**: `LegislatedRepo.Find`, asked by three hooks from three
different starting points, and `ExecutableLookup.Which`, without which "a
machine carrying only one toolchain" cannot be built in a test.

The hooks ruler was driven against the binary for the first time since the T-07
rename — unmeasured for four tasks, its last number taken under the name
collision that made it meaningless. It reads **65 ok / 0 FAIL**. Then the same
question T-10 asked of the engine, in the form this ruler needs: `/bin/false`
proves nothing about a guard, because exit 1 is neither allow nor block, so the
probe is **`PARITY_HOOK_CMD=/bin/true`** — an arm that only ever allows. Under
it the ruler reports 44 ok / 21 FAIL. Only twenty-one of the sixty-five call
sites assert a refusal; twelve never drive the arm at all, and the rest are
assertions of silence, which silence imitates perfectly. `format_on_edit` has
no block label whatever, so its four twins are satisfied by a hook that runs no
formatter: its real coverage is the twelve unit tests asserting on
`FakeProcessRunner.Calls`. All of it is in `parity-hooks-green.txt` rather than
in anyone's head.

`docs/ai/baseline.md` moved, and this time the movement is honest. R-641…R-647
and R-701 gained an annotated test because `GuardGitConductTwins.cs` carries
`per R-641` and the rest inside the `[Parity]` labels — and the claim is true:
those twins do test those requirements. It is the mirror image of T-08, where

formatted by the .NET arm and not by the Python. The ruler cannot see it and
the hook is best-effort polish, but it is a difference, and it is written down.
